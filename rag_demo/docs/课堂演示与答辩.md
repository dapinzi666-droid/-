# 课堂演示与答辩

## 1. 汇报边界

我们选择任务 2 的 **A：基础 RAG 系统**。演示使用虚构的「星河大学图书馆制度」，目的在于验证技术流程；它不是任何真实学校的政策。

老师要求全组严格 **5 分钟以内**，程序演示工程师约 **1–1.5 分钟**。老师给出的各环节时间是建议，直接累加可能超过 5 分钟，因此全组必须实际计时。可参考：开场 40 秒、原理 2 分钟、程序 1 分 30 秒、总结 20 秒，留出约 30 秒切换余量。全员都要有口头输出。

## 4. 三项实验怎么展示才合格

| 老师要求 | 屏幕上应看见什么 | 你要说明什么 |
| --- | --- | --- |
| 简单段落 vs overlap | 同题、两种设置、检索片段、来源和模型回答 | 证据是否完整、是否跨边界、回答差异在哪里 |
| temperature=0 vs 1.0 | 相同问题与上下文下的真实输出 | 本组实际观察，随机性与准确性的区别 |
| 现场检索与 RAG 回答 | 可见的现场执行、检索证据、来源、生成回答 | 答案是否能够由资料支持 |

可以提前运行完整对照实验并展示真实结果；现场仍优先运行一次实际问答。老师要求的是能演示、能解释的实验，不能只展示安装成功，也不能全程只播放视频。

temperature=0 在本项目按确定性生成处理；temperature=1.0 使用采样。若要观察随机性，可以重复采样，但应保留每次真实输出，不能只挑一句看起来漂亮的回答当作普遍规律。

## 5. 现场故障的兜底方案

1. **没有正常投屏**：先检查 HDMI、投影输入源和屏幕复制设置。不要把运行环境临时搬到没有依赖的讲台电脑。
2. **Notebook 连接或单元出错**：确认本机启动终端仍在运行，检查内核是否存在；只有在确实有时间且已经预演恢复步骤时才重启。重启后需要重新加载模型和索引。
3. **内存不足或生成明显超时**：不要不停重复点击。说明现场故障，切换到提前录制的真实演示录像，并由你口头讲解检索和实验结果。
4. **模型下载失败**：课堂上不临时赌下载。模型准备必须提前完成；若事前无法完成，则该电脑还没有满足演示条件，应换用已验证的电脑。

录像仅在现场无法运行时使用。切换时可以直接说：

> 现场运行出现了 [简述实际故障]，这里播放我们课前在同一项目上实际运行的备用录像，检索片段与实验结果已保存，接下来我解释关键现象。

这比展示预写答案更诚实，也符合老师要求的备用方案。录像或缓存结果不能被描述为现场刚生成的输出。

## 6. 老师可能问什么

### 「你们是不是把答案提前写好了？」

没有。资料预先提供，模型和依赖也提前准备，但回答由真实 Qwen 模型生成。展示时可以指出代码读取的资料、实际检索片段和本次输出；项目没有固定答案或模板后备。若模型没下载成功，程序会报错，不会伪装生成成功。

### 「RAG 和普通大模型问答有什么区别？」

普通问答主要依赖模型训练时学到的知识；RAG 先检索本组提供的资料，再把相关证据连同问题交给模型。它可以利用外部新资料并提供来源，但仍会出现检索遗漏、理解错误或幻觉。

### 「你们训练或者微调模型了吗？」

没有。我们使用现有 Embedding 模型和生成模型。建立向量索引是整理检索资料，不是在更新语言模型的权重。

### 「为什么做 overlap？」

信息可能被切分边界截开。让相邻片段共享部分内容，有机会保留联系；代价是资料重复、索引占用与检索冗余增加。是否改善本组问答，要看真实对照实验。

### 「为什么 temperature=0 仍可能答错？」

温度控制生成选择的随机程度，不负责验证事实。模型可能误读证据、加入资料没有的信息，或根本没拿到正确片段，所以仍需核对来源。

### 「为什么 temperature=1 两次看起来一样？」

采样不保证每次输出不同。上下文和提示可能使少数答案概率很高，回答也可能只有措辞微调。可以重复实验观察，但不能为了显示差异修改输出。

### 「如果资料里没有答案怎么办？」

提示模型说明资料不足，并展示检索内容。但小模型未必每次遵守提示，因此不能把它的回答当成事实。可以展示一个实际失败或资料不足的例子，说明系统边界。

### 「Chroma 是什么？要不要单独装数据库？」

它是向量数据库。本项目通过 Python 依赖以嵌入式方式使用，保存资料向量并进行检索，无需独立部署数据库服务。

### 「向量检索是不是查关键词？」

本项目用真实 Embedding 模型把文本和问题转换为向量，再按向量相似程度检索。它能表达一定的语义相关性，但仍可能漏检；不能把关键词计数冒充这一流程。

### 「为什么使用这么小的模型？」

为了降低在普通电脑上的资源要求，便于课堂演示和复现。代价是答案质量与指令遵循能力有限，所以我们核查实际输出，不宣称达到商用系统效果。

### 「本组有没有完成全部验证？」

按实际情况回答。交付时开发云端的模型下载被 HTTP 403 阻断，不能把静态检查、代码生成或模拟测试说成真实模型实验通过。只有在最终演示电脑上完成模型准备、离线验证和完整实验后，才能说明这些环节通过。若仍未完成，应明确指出未完成项。
