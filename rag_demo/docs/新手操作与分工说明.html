任务 2：新手操作与分工说明

1. 你究竟要完成什么

你的角色是「程序演示工程师」。按老师 Excel 的「分组汇报要求」：你需要把代码调试好、准备能运行的电脑，在课堂用约 1–1.5 分钟展示程序和实验现象，然后切回 Notebook 或 PPT。你需要能解释代码的主要步骤，但无需从零写出每一行，也无需独自包办全组的理论、PPT 和总结。

「任务 2」是小组共同完成的代码实践。你先把程序和实验准备好，其他组员才能依据真实结果完成原理讲解、对比分析和汇报材料。全组仍需完成任务 1 的理论梳理；任务 2 的程序不能替代任务 1。

老师的硬要求来自 Excel「分组汇报要求」的 A41–A58；分工来自 A16:D16；全组时间和展示规则来自 A62–A64。本文不包含分组登记中的个人信息。

2. 为什么选择 A

C-2：Milvus 从 Chroma 迁移 Milvus，调整 nlist/nprobe 并观察召回变化 还需处理数据库与索引配置

我们选择 A，因为它能够完整展示「资料如何变成回答」的过程，不需要视觉模型或独立数据库服务。

选题 A 三项必做

  1. 切分对照：对同一份资料，比较「简单段落切分」和「带 overlap 重叠切分」，观察检索片段及问答效果。
  2. 温度对照：对相同问题和相同检索上下文，比较 temperature=0 与 temperature=1.0 的真实模型输出。
  3. 现场问答：显示问题、实际检索到的资料片段、来源，以及模型根据这些资料生成的回答。

只有安装成功，或者只问出一个答案，还没有完成这三项要求。

3. 程序在做什么：用一句话解释每一步

把 RAG 想成「先翻资料，再组织答案」。

  1. 资料：读取 data/knowledge.txt。本项目使用我们编写的虚构「星河大学图书馆」制度，只用于实验，不能当作你所在学校的真实规则。
  2. 切分：把长资料分成小片段；overlap 表示相邻片段保留一部分重复内容，帮助跨边界的信息保留下来。
  3. Embedding：BAAI/bge-small-zh-v1.5 把文字转成数值向量，便于比较问题和资料的语义相关程度。
  4. 向量库：Chroma 在本机保存和检索这些向量。它以嵌入式方式运行，无需另装一个数据库服务器。
  5. 检索：把问题也转成向量，找出相关片段，并显示来源。
  6. 生成：Qwen2.5-0.5B-Instruct 阅读问题和检索片段，生成中文回答。

第一次下载完成后，程序在你的电脑上执行这些步骤。这里没有调用付费大模型 API，也不要求你训练模型。

4. 需要安装什么，电脑要多好

必须准备

  • 一台能安装软件的电脑：Windows、macOS 或 Linux 均可。Windows 新手建议使用 64 位 Python 3.11；项目使用 Python 3.11/3.12。
  • 内存建议 16 GB，8 GB 可尝试，但需关闭不必要的软件；至少预留约 8 GB 磁盘空间供依赖、模型和缓存使用，实际占用随平台而变。
  • 首次安装依赖和下载模型时需要联网，且网络需要能够访问相应下载站点。
  • 浏览器，用于打开 Jupyter Notebook。Notebook 是浏览器里的交互式代码文档。

你主要自行安装 Python。PyTorch、Transformers、Chroma、Jupyter 等 Python 依赖由项目的安装脚本统一安装。无需单独购买软件、购买 API、安装独立数据库、配置 GPU 或下载训练数据。

Qwen 模型的 fp16 权重约 1 GB，但 CPU 运行时可能按 float32 加载，加上依赖、检索模型和运行过程会占用更多内存。这是小模型，回答质量有限，不能把输出当作已验证的事实。电脑性能不同，模型加载和生成耗时也不同；课堂前必须在实际电脑上试运行。

Windows：第一次安装

  1. 从 Python 官方网站 https://www.python.org/downloads/windows/ 找到 Python 3.11 的 64 位 Windows 安装包。不要因为首页显示更新版本就直接换成未验证的新版本。
  2. 安装时勾选 Add python.exe to PATH，再完成安装。
  3. 把整个项目文件夹解压到普通目录，例如 D:\rag_demo。不要在压缩包预览窗口内直接双击运行。
  4. 双击项目根目录的 setup_windows.bat，等待依赖安装完成。安装过程中保留窗口，若失败，记录最后的报错文字。
  5. 在项目文件夹空白处右键，选择「在终端中打开」。确认当前目录里能看到 run_demo.py。

以下 Windows 命令使用 PowerShell。直接调用项目内虚拟环境的 Python，无需更改 PowerShell 的脚本执行策略：

# 只下载和准备真实模型，首次需要联网。
.\.venv\Scripts\python.exe run_demo.py --prepare

# 模型准备成功后，运行离线验证。
.\.venv\Scripts\python.exe run_demo.py --smoke

# 生成完整实验结果，预留足够时间。
.\.venv\Scripts\python.exe run_demo.py --experiments

第一次可以先执行快速实验，了解程序是否完整跑通：

.\.venv\Scripts\python.exe run_demo.py --experiments --quick

快速实验适合排查环境与预演。正式整理报告前，运行完整实验并核查其输出。

macOS / Linux：第一次安装

准备 Python 3.11 或 3.12，在项目目录打开终端，依次运行：

bash setup_unix.sh
./.venv/bin/python run_demo.py --prepare
./.venv/bin/python run_demo.py --smoke
./.venv/bin/python run_demo.py --experiments

如需快速预演：

./.venv/bin/python run_demo.py --experiments --quick

安装脚本会按操作系统选择 PyTorch 安装方式；不要把仅适用于 Linux CPU 软件源的命令直接复制到 macOS。

5. 如何打开 Notebook 并实际演示

  1. Windows 双击 start_notebook_windows.bat；macOS/Linux 在项目目录运行 bash start_notebook_unix.sh。
  2. 浏览器出现 Jupyter 页面后，打开 task2_rag_demo.ipynb。如果浏览器未自动打开，使用终端输出的本机地址；不要关闭这个终端窗口，也不要把包含访问令牌的地址发到公开群。
  3. 选择项目环境对应的 Python 内核。可以先看 Notebook 中的环境检查，确认使用的是项目 .venv。
  4. 依照 Notebook 从上到下运行。选中一个单元后按 Shift + Enter 执行；左侧仍显示正在运行时，先等待它完成。
  5. 提前完成模型准备和建立索引的单元，然后试一次问答。首次运行应留出充足时间，课堂上无需重新下载模型或安装依赖。
  6. 完整实验在课前生成并核查。正式演示优先展示已验证的对照表，现场运行一次单独问答，保留检索片段与来源。
  7. 演示结束切回 Notebook 的结论单元或 PPT，把发言交给下一位组员。

不要在课堂倒计时开始后才点击「全部运行」。重启内核会清空内存中的模型和索引状态，需重新运行准备单元，因此正式开始前确认它们已经就绪。

6. 如何判断真的做完了

  • --prepare 成功：模型确实下载完成，而非只有代码文件。
  • --smoke 成功：真实模型可以在已准备环境中完成基本流程。
  • --experiments 产生可读取的真实结果，覆盖切分对照、温度对照与检索回答。
  • results/ 中的 JSON、CSV、HTML 来自实际运行，能与 Notebook 或终端输出相互核对。
  • 你逐条对照 data/knowledge.txt 检查答案，记录正确、遗漏或幻觉情况，能解释至少一个观察。
  • 实际上台所用的电脑完成预演，并准备好录屏。

目前交付时的验证边界：项目开发云端访问模型下载资源时遇到 HTTP 403，尚不能据此声称真实模型的完整实验已经在云端通过。应在可正常下载模型的电脑上完成上述模型验证与实验。程序没有固定答案或模板后备；下载失败会明确报错，不会把模拟回答包装成成功。

实验报告只能使用真实结果。不能预填模型答案、手工修改排名来制造现象，也不能保证「overlap 一定更好」或「temperature=1 一定说出不同答案」。若结果没有明显变化，如实记录，并分析资料、问题、模型和切分设置对结果的影响。

7. 常见问题

下载失败、403 或连接超时

先保存报错，区分是 Python 依赖下载失败，还是模型下载失败。换用确实可访问相应站点的网络后，再运行 --prepare。不要关闭 TLS 校验、下载来历不明的模型、把登录令牌发到聊天里，或认为错误消失就代表模型准备成功。 如果学校网络受限，可以提前在另一处合规可用的网络上，用最终演示电脑完成下载；模型就绪后再验证离线运行。

提示找不到 Python 或找不到 .venv

确认 Python 已安装，关闭后重新打开终端。确认自己在项目根目录，并且先运行了对应的 setup 脚本。.venv 是安装脚本创建的项目专用环境；它不是需要你去网上另下的软件。

模型运行慢，或内存不足

先关闭大型软件，使用快速实验确认流程；完整实验提前完成。若实际电脑仍不能稳定运行，借用内存更充足的组员电脑并重新安装、预演。不要临时随意更换模型后仍沿用旧实验结论。

temperature 到底是什么

它控制生成时选择词语的随机程度。本项目的 temperature=0 按确定性生成设置处理，temperature=1.0 开启采样。采样可能仍产生相同回答；温度为 0 也可能出现幻觉，绝不代表答案一定正确。观察时要固定问题与检索上下文，并同时检查答案是否忠于资料。

为什么不只给一个网页或 PPT

老师要求可演示代码与对照实验。Notebook 能同时展示代码、问题、检索片段、回答和对照结果，方便回答「你们到底怎么做的」。PPT 负责精简讲解，不能替代真实运行。
